# 需求 57 / 59：原因后的应对措施与推荐追问

健康原因分析完成后，按 `health_solution.possible_causes` 语义关联已有原因，每组最多展示一个完整场景的措施摘录。查询只读，不触发导入、迁移或修改知识库。保留原始场景、关联原因、来源 ID 和审核状态；先用物种、品种、阶段及原文年龄限制过滤，再由模型选择合法的场景 ID / 原因索引。用户描述与场景矛盾时不关联，未知条件显示为待核对情形。

原始方案包含未核验的用药、补充剂、禁食及治疗性饮食安排，不能作为直接执行的治疗方案。服务仅摘录观察、记录、环境与就医措施，不截断改写带剂量的步骤，也不沿用依赖治疗的等待期限。无法安全摘录时提示由兽医评估；无匹配或读取失败仅影响措施，已完成的原因分析仍可展示。纯文本同时保留措施，兼容旧客户端。小程序按每组三个原因分页，措施与原因一起翻页。

产品推荐成功时保存三个方向的问题：功能描述对比、蛋白质和脂肪资料、适用性缺失信息。单产品和仅品牌资料使用相应措辞；无推荐时不生成追问。点击传 `source_message_id`，后端核验所有者、会话、宠物及原问题，并从对应历史推荐卡回答。换组后仍可询问旧卡；推荐库 `product_key` 不转换为配方 ID，也不推测营养数值或评分。临时点击来源不持久化到会话状态。
