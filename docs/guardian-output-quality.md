# 管家输出质量复测（2026-11-14）

本轮承接需求53、54，优化连续对话的正文和追问，使用完整线上数据库按真实业务过滤检索。没有把部分知识快照、空健康映射或固定产品画像当作验收数据。

## 改动

- 正文只展示完整、独立可读的简短结论，上限220字；理由、缺失信息和来源保留在结构化字段中，不再逐段追加造成重复。隐藏字段仍校验来源、结构和不支持的确定性断言。
- 单点追问只带明确来源及必要用户事实，不自动附加最近的其他产品报告；单纯产品指标问题不带无关健康记录。综合判断仍保留症状、时间纠正和产品证据。
- 记忆明确保留同维度比较数值、量表和差值。相对市场的标签不能当作两个产品之间的大小关系；相同数值必须回答相同。
- 问哪款能解决健康症状时进入有依据的综合回答，不重复整份比较报告。不把单次检查未检出当作排除依据，也不把待核验线索当作确诊条件。
- 新生成追问不超过28字，使用主人向管家请教的口吻；校验重复、当前原问题和长度。生成时提供当前卡片的产品范围，避免凭空出现第二款粮，并要求推进不同信息点；可选追问生成失败时仍保留已有问题。
- 比较文案移除未经用户确认的“恢复期”前提，保持现有分数和比较规则。
- 全量数据下发现健康总结常返回4条短症状，而卡片要求至多3行，导致整条回答失败。新增无损格式整理：将短项合并为不超过100字的行，不删事实、不删来源；无法完整容纳或类型错误的内容仍由原校验拒绝。

## 数据与验收方法

线上库存：健康原因明细815条、汇总知识328条、通用知识明细774条、营养规则24条、指标绑定11条、产品画像103款、健康映射21条、市场比较103款。猫便臭按实际物种、问题和审核状态过滤得到22条原因明细。

验收在服务器独立Python进程使用候选代码、生产配置、真实模型和所有现有读取模块。SQL拦截器禁止写入，既有标准化表验证存在后跳过初始化DDL；只用内存中的合成宠物及会话，不写用户记录。产品目录、配方、计算版本、画像、健康映射、营养规则和社区查询均走实际读取。模型仍按业务筛选、上下文预算使用相关数据，并非一次把整库全部塞入模型。

主链路：便臭→分别分析冠能两款粮→比较→综合归因；六种追问各复测两次，包括寄生虫单点、记录方式、纠正时间、效果保证和具体差异。补充验证真实旧卡片问题、通用知识换话题后返回、益生元相同分数两次、检查阴性边界。

旧版两个上下文样本正文分别405、383字。本轮上下文正文一般约80～160字，保留回答当前问题所需的依据和下一步。益生元复测均明确“两款都是1.56/5，没有谁更高”，没有再把市场标签误当成产品间分差。

通用玩法问题查到了相关记录，但缺少足够适用依据，系统明确说明资料不足；未把检索命中当作可靠答案。这个知识覆盖限制仍存在，不将本轮验收等同于知识库全部内容已专业核验。
