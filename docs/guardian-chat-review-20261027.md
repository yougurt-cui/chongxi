## 二、按影响排序的问题

### P0-1 「幼猫」被吃掉三次，最后给了成猫减重方案

- `10:48:40` 用户「幼猫选粮要注意什么」→ 立刻被判定 `food_switch`，回「它目前有什么身体问题或相关病史？」
- `10:50:02` 用户「幼猫选粮」→ 原文不动，又回「这次最希望改善哪一方面？」
- `10:50:18` / `10:52:30` 两次输出**一字不差**的「本次按「无明显问题＋减重」筛选」，候选全是成猫/全阶段粮。
- `10:52:25` 用户「幼猫喂养」→ 仍然吐同一份减重方案。

根因：
1. `guardian_workflow.requested_flow()` 命中「选粮」就切 `food_switch`，把"问标准"当"要我选"。
2. `INTENT_SLOTS['food_switch']`（miniprogram_chat_service.py:62）没有生命阶段/年龄槽位，`goal_options()` 的 8 个选项也没有「幼猫/生长期」，所以"幼猫"这个约束**无处安放**，只能当噪声丢掉。
3. 该猫档案 36 月龄，用户问幼猫属于对象冲突，系统既没澄清也没提示。

### P0-2 知识库靠 2-gram 硬凑，答非所问

- `10:47:09`「想了解适合我家宠物的日常饮食建议」→ 回「猫尿闭」「黑下巴」。
- `03:06:51` / `07:14:09`「日常养宠有哪些饮食、清洁和陪伴方面的注意事项」→ 回「黑下巴」「猫咪钻床底」，**"陪伴"一个字没答**。且两次同题结果不同（一次 4 条资料+完整结论，一次 2 条+回退文案）。

根因：`guardian_knowledge_service.plan_query()` 把问句拆成 2-gram（「清洁」「陪伴」→ 甚至「是球」这类碎片），`retrieve()` 用 `term in content` 判命中，既没有相关性下限，也没有宠物领域过滤。与上一轮"今天天气怎么样"命中的是同一条根因。

### P0-3 换粮流程会抢走知识性问题，还会丢上下文

- `10:48:40`「幼猫选粮要注意什么」是问标准，被塞进选粮问卷。
- `07:15:58`「- 换粮时如何观察猫咪的适应情况」（这是系统自己在"大家还在问"里给出的问题，用户连破折号一起复制）→ 被当成全新话题，从"身体问题"重新问起，前一轮已填的健康状态、目标、候选粮全部作废。

根因：`requested_flow()` 是纯正则先命中，优先于 `_recognize_guardian_turn()` 的语义判断；且以 `-` 开头的粘贴文本没有被清理。

### P1-4 结构化失败率 30%，回退文案劝退

3 次 `evidence_fallback` 的开场白都是「找到以下相关资料，可结合具体情况参考；目前无法进一步整理结论。」

- `guardian_knowledge_cards.validate()` 校验很硬：evidence 必须与源文本整行完全一致、conclusion ≤60 字、禁止新数字，2 次重试后仍不过就走 `cards.fallback()`。
- 顺带发现数据脏点：`kd_problem_guides.id=54`「球虫感染」的 `pairs_json` 原文就是「需使用专门针对球虫的驱虫药（**如某红糖**）」，脱敏残句被原样展示。

### P1-5 跨品牌产品必然查不到，导致"资料不足"与"已有资料"自相矛盾

- `07:16:22` 换粮方案明确列出「鲜朗 兔肉烘焙猫粮」的目标配料与包装营养标示（粗蛋白≥50%、粗脂肪≥20%）。
- 1 分钟后 `07:17:25`「鲜朗兔肉有什么特点吗」→「目前没有可核验的配方分析，**资料不足**，无法确认其配料、营养值或适口性」。

根因在 `miniprogram_chat_service.py:770-774`：用户没指定品牌时，`brand` 回落到宠物档案的 `food_brand`（蓝氏），于是拿「蓝氏 + 鲜朗兔肉」去查候选，必然 0 条。同理 `07:21:26`「蓝氏猫粮」也查不到——产品名没做规范化（品牌词没剥离、没做候选展开）。

### P2-6 追问与选项本身不解决问题

- 「这次最希望改善哪一方面」在 `10:49:51 / 10:50:05` 连续弹两次，`followup_count` 涨到 3，用户每次都在说别的，系统每次原地重问。
- `07:15:09`「饮食上有什么推荐吗」→「…若出现挑食，可参考将**某品牌**奶糕粮作为辅助选择」。脱敏后的品牌空壳对用户零价值——要么给出可核验产品，要么明确说查不到。
