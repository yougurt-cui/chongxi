# 2026-10-12 管家体验反馈：历史口粮回答与继续选粮

## 问题与修复

管家询问“以前吃过哪些主粮，吃的时候便便怎么样？”后，用户仅回答“蓝氏猎鸟乳鸽”。既有规则需要“以前/吃过/主粮”等字眼才能记录历史，模型未补齐历史字段时，这句产品名被视为未回答，下一轮将历史步骤标记为 deferred。

这不是蓝氏产品不存在：生产标准目录包含“猎鸟乳鸽全价猫粮”和“猎鸟乳鸽2.0”。本次改动是在明确等待历史口粮回答时，用上一问题理解省略回答，保留用户原话和消息来源；不假定是哪一版配方、不推测吃粮日期或便便表现，不改当前口粮。模型抽取为空或不可用时也能保留该回答。

“嗯”“好的”、不知道/拒答、选粮请求和话题切换不能当成历史口粮；其他提问场景也不能使用这一补齐规则。A粮等演示别名在历史问题中不自动填成新粮。

修复由 `fix/guardian-history-food-reply` 分支提交 PR #3，已于 2026-10-12 合并 main、push 并重新部署，功能发布提交 `641b7de`。服务器上的抽取函数已验证裸产品名及原文来源正确保留、不填成当前/新粮；服务健康与内网/公开 HTTPS 鉴权检查通过。部署前后服务器已有两处本地修改的 SHA-256 一致，未更改既有生产会话。

## 继续选粮已经支持

后端在综合建议结束且无高风险信号时，返回 `flow_handoff` 操作，目标为 `food_switch`，显示“继续聊选粮”。客户端也可直接发送“帮我推荐一款主粮”，不必等待按钮。选粮流程保留当前粮、用户补充的历史及其他上下文，再补充改善目标并调用现有推荐引擎。

2026-10-12 生产只读检查确认：

- 相关完成会话已经返回 `flow_handoff → food_switch`，入口并非尚未开发。
- 标准目录有 131 条当前有效配方，其中 40 条有适用阶段；评分库有 117 行，推荐画像有 6 条。
- 以猫、无疾病/过敏标签的匿名档案及肠胃改善目标检查现有推荐函数：年龄未知返回 `no_eligible_food`、0 候选；24 月龄返回 `ready`、3 候选。这里是代码及数据可用性验证，不是为真实宠物选择粮款。
- 反馈相关宠物的 `age_months` 为空，需要在档案补充年龄/生日，不能由模型猜测适用阶段。
- 配套小程序 PR #1 已合并至 dev；没有据此认定微信已发布或负责人手机上的版本已更新。若没有按钮，仍可文字发起选粮。

产品资料不足、有疾病背景或偏好无匹配时仍会降级，不能把“支持流程”理解为任何档案都一定能返回具体粮款。

以上年龄为空不返回候选的结果是 PR #3 发布时的旧规则。2026-10-12 负责人后续要求放开，后端 PR #4 已调整为年龄选填、未填也可推荐，并接入选粮/换粮对话步骤；见 [年龄调整与流程融合说明](guardian-food-flow-integration.md)。历史口粮修复及年龄调整均只涉及后端，无需修改小程序代码。
