# 管家对比粮：因子证据链改造（2026-10-27）

## 一、为什么"对比结果都差不多"

不是文案模板化，是**对比维度本身没有区分度**。

旧链路只做一件事：比较五个结构分，用固定阈值（归一化差值 ≤0.10 判"接近"）。三个硬伤：

| 问题 | 表现 | 数据 |
|---|---|---|
| 归一化基数错 | `prebiotic_score` 按 5 归一，但全库最大只有 2.18，归一后最大值 0.44 | 63% 的配方必然"益生元偏低" |
| 分数区间窄 | `protein_score` 全库 0.15–0.70，永远够不到 0.75 的"偏高"线 | "蛋白质量较好"成固定标签 |
| 阈值拍死 | 用绝对差值而非相对位次 | 300 对采样里，蛋白压力被判"共同特点"占 **64%** |

量化结果：采样 25 个配方、300 对组合，抹掉数字后旧版结论结构唯一率 **70%**（也就是 30% 的对比完全同构）。

同时还有两个断点：

- `guardian_food_flow_service.py:251` 只加载**目标粮**的风险数据（`load_risks([selected['formula_id']])`），原粮的软便/黑下巴标签根本没进内存，所以对比时无话可说；
- 换粮方案分支（`planned`）连"已选定"分支那 4 行风险渲染都没有，用户只看到一句免责声明。

## 二、改造：三层证据链

新增 `services/guardian_factor_evidence_service.py`（约 570 行），把"分数比较"换成"位次 + 标签 + 经验"三层。

### 第一层：结构位次（解决"差不多"）

用**全库分位**替代固定阈值。分位是相对排序，天然有区分度：

```
· 脂肪结构：原粮 36%，目标粮 12%，目标粮压力相对更低
· 菌群与益生元：原粮 60%，目标粮 21%，目标粮支持相对更少
```

同时明确一件事：这些分是**压力/负担**，不是营养质量。`protein_score` 高 = 消化压力大，不等于蛋白好——这修掉了旧版"蛋白压力接近"和"蛋白质量较高"同段打架的问题。

### 第二层：风险标签（解决"因子与疾病没挂上"）

`sku_risk_score_result` 的两个模型（SOFT_STOOL / BLACK_CHIN，125 配方 × 2）本来就在输出**因子级标签**，只是从没被对比链路读过。

模块把标签拆成两侧：

- **结构侧**（配方成分）：碳水结构压力偏高、蛋白结构偏复杂、脂肪负担偏高、纤维支持偏弱、益生元支持偏弱……
- **功能侧**（肠道机制）：SCFA 支持偏弱、菌群代谢支持不足、肠道缓冲支持不足、吸水成形能力偏弱、粪便骨架支持偏弱……

这两侧接起来，正好就是"因子 → 机制 → 症状"：

```
· 软便：原粮：碳水结构压力偏高、SCFA支持偏弱（中高软便配方风险）；
        目标粮：吸水成形能力偏弱、菌群代谢支持不足、肠道缓冲支持不足（低软便配方风险）
· 黑下巴：原粮：碳水结构偏高（中低配方风险）；
          目标粮：Omega-3支持不足、脂肪调节支持不足、益生元支持偏弱（中低配方风险）
```

关键设计：**按症状对齐，不按配方对齐**。旧逻辑是"A 粮有什么、B 粮有什么"，读起来像两个不同的病；现在同一条症状下横着看两款粮，差异立刻可见。

标签的全库分布支持这个做法：软便模型的 `main_reason_tags` 有 44 种不同组合 / 226 行，区分度足够。

### 第三层：社区经验（评论蒸馏）

`kd_problem_guides` 的 1701 条里，有 172 条涉及软便/黑下巴/便便等。模块按"因子 + 症状"关键词取**成因侧**（`cause`），不用对策侧（`action`）——对策属于医疗建议，不应该出现在选粮对比里。

两道硬门槛是必须的，否则会误命中：

- 必须有饮食语境词（粮/食物/配方/喂/吃/饮食…）
- 必须不含药物词（霉素/注射/给药/抗生素/激素…）

加门槛前会捞出"庆大霉素口服吸收差，主要在肠道局部起作用"这种条目；加门槛后剩下"食物配方结构不合理、碳水化合物摄入过多"这类真正相关的观察。

所有条目强制标注 `evidence_status`（几乎全是"待验证"）和一句总免责。

| 指标 | 旧版 | 新版 |
|---|---|---|
| 结论结构唯一率 | 70%（211/300） | **100%（300/300）** |
| 首句唯一率 | — | 96%（289/300） |

首句那 4% 重复来自同一原粮对不同目标，差异本身是真实的。

### 边界

| 场景 | 行为 |
|---|---|
| 风险标签缺失 | 回退旧版五维三段式（`factor_ready()` 为假） |
| 原粮未识别（`comparison_id=None`） | `status=unavailable`，输出提示不崩 |
| 原粮 = 目标粮 | `status=same_formula`，提示"同一个配方" |
| 位次都缺失 | `status=partial`，只出标签差异，不推算症状 |
