# 需求49：管家切换多模型知识库

来源：宠析需求池第49项，实际第52行，revision 923，2026-11-08核对。

## 核实结果与范围

生产新库为 `chongxi_model_knowledge`，问答内容位于 `knowledge_point_source`，通过 `batch_id` 关联 `knowledge_import_batch`。字典在 `chongxi_knowledge_dictionary`。检查时共48条，DeepSeek 23条、千问25条，豆包暂无记录；内容均涉及布偶猫喂养，不能宣称已覆盖所有物种或三个模型。

知识表字段：id、batch_id、source_provider、original_condition、species_code、breed_code、life_stage_codes、need_codes、category_code、topic_code、content、standardization_meta。批次提供原始模型、task_id、采集状态和联网来源。`standardization_meta.provider=qwen` 只是标签标准化执行者，不能算作知识的第二个来源。success不代表专业审核通过。

实际数据存在同题多来源、重复观点、营养比例分歧、商品宣传数据，以及“原文成猫但stage=unspecified”的情况。阶段词典中的unspecified不等于all_stages；原文年龄范围可能比字典更窄。新库未提供专业审核字段，统一按未验证模型资料处理。

本次确定范围：

- 养宠知识问答、普通健康咨询（含图片综合提问）统一检索新库。
- 软便保留既有分诊、信息补充和分析状态，完成非紧急分析后补充有来源的知识卡；紧急情况直接进入原风险提示，不等待知识模型。
- 管家的旧`kd_problem_guides`召回全部暂停，包括产品报告和因子解释的旧社区知识引用；不删除旧库、不修改采集/定时生产配置。产品报告仍可展示独立的`cat_disease_clues`真实社区反馈，模型知识不冒充社区经验。
- 产品配方、评分、推荐开关、上传、提醒、日常状态等原有业务流程不切换到模型知识库。新库`product_goods`不能代替已核实的SKU及配方数据。
- 普通知识空缺沿用需求41的通用补答与缺口记录；健康咨询不做无限制通用补答。读取失败不算覆盖缺口，也不回退旧知识库。

## 实现

新增`services/guardian_point_knowledge.py`，仅SELECT新知识表、批次和四张标准词典，不导入生产采集writer、不建表。默认使用现有MySQL连接，独立库名可通过`GUARDIAN_KNOWLEDGE_DATABASE`和`GUARDIAN_DICTIONARY_DATABASE`调整；标识符严格校验，用户文本参数化。

检索按当前问题/同对象连续追问及字典主题、需求扩展；先在SQL中限定采集成功、标准化成功、来源一致、物种和品种，按相关性排序后最多读取240条候选。程序继续校验阶段及原始条件，未知品种不套品种专用知识；确诊/妊娠等无法确认的条件不自动采用。相同来源、相同适用条件及正文精确去重，保留重复ID；最终最多12条，并为实际命中的各来源保留候选位置。没有相关资料的来源不会为了凑三个模型而加入。

复用一次回答整合模型，而非每次重新调用三个采集模型。提示词要求合并同义信息、保留互补内容和原始适用条件，冲突不投票、不平均、不擅选。冲突必须引用双方并出现在注意事项中；未验证的营养比例不得作为喂养指令。保留来源行号引用校验与一次有时限的格式修正。整合失败仅提示稍后重试，不直出新库原始模型断言。

沿用现有消息接口、卡片和文字兼容字段。`knowledge_qa.version=3`，`source_table=knowledge_point_source`，记录实际采用point_ids、候选ID、来源提供商/原模型/批次/任务、原始条件及冲突。旧guide_ids保留空数组作兼容；缺口表现有candidate_ids_json保存新库候选ID，消息元数据标明来源表。记录随聊天持久化、历史回看不重新检索。

无需小程序发布或生产DDL。保留服务器本次开始前已有的多模型采集模块等未提交文件，部署前后核对摘要。

## 验证与发布

验证记录在工作区 `local-dev/qa49`。包含真实数据快照、改造前回归基线、单元与扩展回归、隔离MySQL/Flask API/真实模型试答及小程序渲染检查。采集库仅只读检查，联调账号和消息写入专用本地qa49_app，不写生产用户数据。

发布前同步最新远端，提交并推送后让服务器fast-forward pull；只重启目标API服务，保留生产进程环境和日志。检查公开HTTPS、鉴权、实际知识查询及受保护文件摘要。若启动健康检查失败，恢复本次修改文件至发布前版本并重启原API。

本次发布候选验证：针对性109项通过、21个子用例通过；扩展362项通过、26个子用例通过，23项失败与原分支逐项一致，无新增失败。真实接口五个场景、缺口入库及历史一致性通过，固定联调小程序实际卡片展示通过。新库覆盖范围仍受现有48条布偶资料限制，其他物种/品种会明确走缺口路径，不借用布偶资料。
