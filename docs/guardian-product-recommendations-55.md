# 管家产品推荐（需求 55）

来源：[宠析需求池](https://my.feishu.cn/wiki/H5v3wyrKvib1BckmWEjcSrnln8c?sheet=64b243)，实际第 58 行，2026-11-17 revision 1233。恢复管家选粮流程中的产品推荐，使用 `product_recommendation` 展示品牌、产品和功能概述。

## 行为

- 新服务 `guardian_product_recommendation` 只读 `PRODUCT_KNOWLEDGE_DATABASE`（默认 `chongxi_product`）中的推荐库，使用 `GUARDIAN_DICTIONARY_DATABASE` 的物种、品种、年龄、需求字典筛选。不会在请求中建表、导入数据或调用模型补造产品。
- 默认每组最多 3 个产品，同一 `product_key` 合并适用来源，换组排除已展示产品。需求、宠物资料或历史口粮变化时重新计算筛选范围。推荐按具体产品、品种匹配及来源数量稳定排序；来源数量不是营养评分或有效率。
- 待审核资料可以作为参考展示，并明确提示来源及核验状态。排除被拒绝的记录/来源，保留原文功能描述；不会将品牌级推荐伪装成具体产品，也不把年龄未指明等同全阶段。
- 筛选同时检查原始来源的明确年龄限制，避免宽泛编码覆盖来源限制；疾病、过敏、处方、未恢复的呕吐/肠胃炎不能据此生成普通饮食推荐。价格、产地没有可靠字段时明确无法核验，不声称符合这些偏好。
- 品牌与当前/历史口粮按已知名称排除，不对不同版本进行模糊身份合并。缺少数据、无匹配结果分别返回明确状态。
- 推荐知识与正式配方身份分离：返回 `product_recommendations.version=1`，`food_candidates` 保持空。前端展示资料卡，不显示结构分、配方详情或“更新口粮”操作。旧客户端通过完整回复正文读取推荐。
- 新卡片换组携带会话当前批次的 `refresh_token`，旧卡片、伪造及跨会话 token 返回 400；前端校验当前宠物和发送状态。文本“换一组”继续可用。
- 修复聊天结果中 `slots` 引用后续被会话记忆修改的问题，返回独立快照，使即时回复和历史回读一致。

原 Web `/api/consumer/recommendation/*` 评分演示入口保持原有状态；本需求来自“管家 → 回复”，不恢复旧评分算法。

## 验证

- 新增 23 项后端测试：来源、物种/品种/年龄/原文限制、审核状态、品牌级、去重换组、历史排除、偏好限制、只读参数化 SQL、数据库异常和聊天 token。
- 扩展管家/聊天回归：521 项通过、20 个子用例通过；30 项失败与 `1c47335` 独立基线相同（基线 498 项通过），没有新增失败。旧失败涉及已撤下的推荐接口引用及既有报告/知识期望。
- 真实本地 MySQL 导入线上推荐库 476 条及字典快照，隔离用户、会话和宠物，经 Flask HTTP 验证鉴权、推荐/换组、旧 token 和跨会话 400、无结果、年龄未知/幼猫/狗、历史回读、风险优先及无口粮写入。
- 小程序映射/交互、旧版本兼容、发送和宠物边界测试通过，原鉴权契约及知识卡片测试通过。
- 微信开发者工具固定使用 `local-dev/qa34-miniprogram`；正式页面通过真实本地 HTTP 完成发送、3 张推荐卡渲染、换组、过期按钮、无结果，运行时异常为 0。测试账户存储在结束后恢复。
- 发布前对线上数据运行只读候选代码验收，不修改生产用户、宠物或知识库。记录和截图保留在工作区 `local-dev/qa55`。
