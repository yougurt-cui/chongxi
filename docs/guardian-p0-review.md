## 1. 上传配料照片后，用户知道下一步怎么做

**问题：** 以前可能只生成了图片来源记录，尚未读到配料表，就被当作识别成功；失败后也缺少明确的补拍指引。

**改后体验：** 上传前提示拍包装背面的完整配料表，文字清楚、无反光。结果区分识别中、没读到配料、待核对、服务失败和成功。失败时告诉用户原因并提供重新上传，保留品牌和产品名；只有读到可用配料，才能交给管家分析。

**后端改动：** 按识别节点结果及配料正文判断状态，给小程序返回提示和操作权限；对旧的错误成功记录也校验；聊天入口再次拦截无配料的记录。识别成功与后续审核、产品收录各自判断。

**小程序改动：** 上传表单加拍照提示，详情加结果解释、重新上传按钮，按实际结果显示分析按钮。

**怎么验收：** 上传只有包装正面的图片，不能直接得到配料分析；失败后补拍，不必重填名称；有有效配料后能够进入分析。真实照片识别效果仍需 OCR 联调。

**代码入口：** 后端 `services/miniprogram_food_submission_service.py`、`services/miniprogram_chat_service.py`；小程序 `utils/food-submission.js`、`pages/pet-space/food-submissions.*`。

## 2. 把“实际吃过的粮”保存成云端历史

**问题：** 原有本机历史不能作为稳定的跨设备记录；上传过、咨询过或准备换的粮，也容易被混同为吃过的粮。

**改后体验：** 在口粮清单改当前粮时，原粮自动进入历史。历史页支持补录品牌、产品、吃粮日期和备注，删除错误记录。本机旧记录先让用户核对，再保存到云端，不自动猜测开始日期。

**后端改动：** 新增宠物吃粮历史表及查询、补录、删除三个接口；修改宠物口粮与历史归档一起成功或一起回滚；重复保存同一口粮不增加记录；按登录账号和宠物隔离。

**小程序改动：** 历史页从本机记录改为读取服务端，增加补录表单、日期、备注、删除及旧记录确认导入。

**怎么验收：** 当前粮 A 改为 B 后，当前只显示 B、历史出现 A；再保存 B 不重复；补录历史 C 不改变当前 B；换账号或宠物不能看到对方历史。

**代码入口：** 后端 `services/miniprogram_diet_history_service.py`、`services/miniprogram_cat_profile_service.py`、`api/miniprogram_api.py`；小程序 `pages/pet-space/food-list.*`。

## 3. 历史粮显示当时咨询过的健康话题，供管家参考

**问题：** 管家缺少“这只宠物以前吃什么、那段时间问过什么”的背景，切换到选粮时也不能充分复用已有记录。

**改后体验：** 已知吃粮日期的历史记录旁显示“排便与肠胃（2 次咨询）”等话题摘要。管家在普通对话、软便分析和切换选粮时能够读取这些摘要。

**后端改动：** 只关联同一账号、同一宠物、对应时间段的有效用户咨询；同一话题在同一会话出现多次只算一次。日期不全的手动历史不做关联；当前粮从服务端首次记录起计算。传给模型的是摘要，而不是反复发送原始聊天内容。

**小程序改动：** 历史页展示话题及咨询次数，并说明它仅表示同期咨询。

**怎么验收：** 补录有开始、结束日期的历史，能显示区间内相关咨询；日期未知时不能声称当时没有问题；其他宠物的咨询不混入。

**审查边界：** 同期问过软便，不能据此断言这款粮导致软便；目前未自动把咨询当作推荐引擎的负面反馈。

**代码入口：** 后端历史服务、`services/guardian_workflow.py`、`services/soft_stool_assistant_service.py`、`soft_stool_assistant/llm.py`；小程序历史页。

## 4. 管家给出有数据支持的粮款候选

**问题：** 切到选粮后，仅有上下文和文字建议，还没有接完整的实际粮款筛选与候选卡。

**改后体验：** 用户说明改善目标后，资料充分时显示最多 3 款候选、匹配画像、参考分、理由和需留意项；资料不足时解释原因，先给选粮方向。

**后端改动：** 接入现有推荐画像和评分引擎，与当前标准产品/配方目录对应；按年龄阶段、主粮类型、配料、已知过敏及明确品牌、产地、每斤预算筛选；排除当前粮；所需评分资料缺失就不推荐。

**小程序改动：** 管家结果区增加候选卡；软便建议中的选粮入口进入同一会话的选粮流程。

**怎么验收：** 有完整产品和评分数据时显示真实候选；无数据时不给虚构品牌；每袋预算不被误当成每斤预算。

**审查边界：** 目前使用猫粮库，狗或有疾病标签的宠物先给方向。价格是品牌参考区间，不是实时售价。开发库尚缺完整资料，真实产品推荐仍需联调。

**代码入口：** 后端 `services/guardian_recommendation_service.py`、`consumer_apps/product_recommendation_engine.py`、`services/taobao_sku_import_service.py`、聊天服务；小程序 `utils/assistant-chat.js`、`pages/assistant/index.wxml`、`index.less`。

## 5. 用户确认已经吃了，才更新当前粮

**问题：** “想换 B”或“系统推荐 B”都不能代表宠物已经吃 B，否则历史和后续分析的基础会错。

**改后体验：** 候选卡按钮是“已开始吃这款，更新口粮”。点击后再次确认；确认才更新档案并归档旧粮，取消只保留推荐。后续软便对话使用更新后的当前粮。

**后端改动：** 复用档案 PATCH，根据真实产品、配方 ID 校验并保存；更新后刷新软便饮食基础，避免沿用旧粮分析。手动改名称时清理旧配方 ID。

**小程序改动：** 增加确认弹窗、保存反馈和档案刷新；切换账号、宠物或取消时不保存。

**怎么验收：** 只问推荐或取消确认，档案保持 A；确认“已经开始吃 B”后，当前变 B、历史有 A。
